# 기능별 처리 흐름

SketchCatch는 입력한 요구사항과 저장소, 기존 AWS 자원에서 설계를 만들고 검토한 변경을 배포합니다. 각 단계에서 사용자가 확인할 내용과 서버가 보장할 조건을 정리했습니다.

## 설계 시작

| 시작 방법 | 처리와 확인 |
| --- | --- |
| 요구사항 입력 | 텍스트나 확인한 음성 전사 내용을 바탕으로 AI가 초안을 제안합니다. 사용자가 수락한 뒤 설계에 반영합니다. |
| 저장소 분석 | 실제 파일과 실행 설정을 분석하고 사용할 템플릿과 추가 질문을 제시합니다. 확인하지 못한 내용을 구현된 기능으로 단정하지 않습니다. |
| 기존 AWS 자원 조회 | 연결한 계정의 읽기 권한을 확인하고 결과를 미리 보여 줍니다. 사용자가 선택한 결과만 설계에 반영합니다. |

AWS 조회 미리보기는 사용자와 연결 계정에 묶어 저장합니다. 만료되거나 이미 사용한 결과를 새 결과처럼 다시 반영하지 않습니다. 조회 권한 설정과 실제 자원 배포 승인은 별도입니다.

## 설계 편집

다이어그램과 Terraform 코드는 같은 자원 정보를 기준으로 맞춥니다. 해석할 수 없는 블록은 보존합니다. AI 수정안은 먼저 비교해 보여 주고 사용자가 수락해야 저장합니다. 오래된 탭의 저장 요청이 최신 초안을 덮어쓰지 않도록 버전을 검사합니다.

## 배포 전 확인

1. 프로젝트 소유권과 AWS 연결을 확인합니다.
2. 파일과 설정을 검증하고 예상 비용과 보안 경고를 보여 줍니다.
3. Terraform Plan으로 실제 변경할 자원을 확인합니다.
4. 사용자가 확인한 파일과 대상, Plan을 승인 기록에 묶습니다.

실행 직전에 같은 조건인지 다시 확인합니다. 조회 실패를 변경 없음으로 처리하거나 오래된 승인을 새 파일에 사용하지 않습니다.

## 실행과 복구

승인한 계획은 별도 Worker에서 실행합니다. 인프라와 애플리케이션을 함께 배포하거나 인프라 배포 후 애플리케이션을 이어서 배포할 수 있습니다. Git 저장소의 PR과 CI/CD를 통한 배포도 제공합니다.

DB 작업 번호로 실행 중인 Worker를 다시 찾고 프로젝트별 실행 점유권으로 중복 배포를 막습니다. 완료를 확인할 수 없으면 새 실행을 바로 시작하지 않습니다. 실패한 단계와 로그, 상태 파일을 남겨 다음 확인과 복구에 사용합니다.

## 결과 확인과 정리

배포 결과에서 접속 주소와 실행 이력을 확인합니다. 관측 기능은 실제 조회 결과를 사용하며 AWS 자원을 자동으로 변경하지 않습니다. 자원 삭제는 최신 상태와 소유권을 확인한 뒤 실행합니다.
