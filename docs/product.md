# 제품 소개

SketchCatch는 클라우드 구성을 다이어그램과 Terraform 코드로 편집하고 배포하는 서비스입니다. 설계와 코드가 따로 바뀌는 문제를 줄이고 실제 변경 내용을 검토한 뒤 배포하도록 만들었습니다.

## 사용 흐름

1. 요구사항을 입력하거나 소스 저장소와 기존 AWS 자원을 불러옵니다.
2. 설계 초안을 검토하고 다이어그램이나 Terraform 코드를 수정합니다.
3. 비용과 보안 경고를 확인하고 Terraform Plan으로 바뀔 자원을 확인합니다.
4. 승인한 계획을 직접 배포하거나 저장소의 PR과 CI/CD에 연결합니다.
5. 실행 결과와 로그를 확인하고 더 쓰지 않는 자원을 정리합니다.

## 주요 기능

| 기능 | 동작 |
| --- | --- |
| 설계 입력 | 텍스트와 음성, 저장소 분석 결과 또는 기존 자원에서 초안을 만듭니다. 음성은 사용자가 전사 내용을 확인한 뒤 사용합니다. |
| 다이어그램과 코드 편집 | 같은 자원 정보를 두 편집기에 반영합니다. 해석하지 못한 코드 블록은 지우지 않습니다. |
| 배포 전 검사 | 비용과 보안, 설정 위험을 보여 줍니다. 경고 확인과 실제 배포 승인은 구분합니다. |
| 직접 배포 | 승인한 Terraform 계획을 별도 Worker에서 실행합니다. 작업 이력과 결과를 저장합니다. |
| CI/CD 연결 | 사용자 저장소에 PR을 만들고 GitHub Actions 실행 상태를 추적합니다. PR 생성과 병합, 실제 실행은 별도 동작입니다. |
| 기존 자원 불러오기 | 연결한 AWS 계정의 자원을 조회해 설계와 Terraform import 제안을 만듭니다. 조회만으로 기존 자원을 바꾸지 않습니다. |
| 배포 상태 관측 | 성공한 배포의 요청과 실행 상태를 15분 동안 확인합니다. 조회 실패를 가짜 정상 수치로 대체하지 않습니다. |

## 승인과 실행 제한

- AI가 만든 설계와 수정안은 사용자가 수락하기 전까지 제안입니다.
- AWS 변경은 검토한 Plan과 승인 내용이 현재 코드 및 대상과 일치할 때만 실행합니다.
- 빌드용 CodeBuild에는 서비스 배포 권한을 주지 않습니다. 승인된 파일을 별도 Worker가 배포합니다.
- 관측 화면의 용량 제안을 수락해도 편집 초안만 바뀝니다. 실제 반영에는 새 Plan과 승인이 필요합니다.
- 자원 정리는 사용자 배포의 소유권과 상태를 확인한 뒤 수행합니다.

## 지원 범위

현재 구현은 AWS와 Terraform을 기준으로 합니다. 클라우드별 처리를 연동 모듈로 분리했으며 Azure와 GCP 연동은 확장 방향입니다. 클라우드에서 조회한 내용과 AI 추정을 구분합니다.

임의 URL에 무제한 트래픽을 보내거나 AI가 자동으로 운영 자원을 바꾸는 기능은 제공하지 않습니다.
